# 交付执行

两条路径都先准备交付说明。使用项目既有模板；没有模板时至少写清：具体问题与修复后行为、原始复现及正常对照的前后证据、固定提交和验证环境、影响范围与回退方式、未修项和未验证边界。使用 [批次结果](../assets/batch-result.md) 保存逐项状态，PR/MR 正文按读者需要引用证据。

`mattpocock/skills` 的 `pr` 是可选增强，按实际安装位置解析并完整读取；没有安装也可执行以上规范。项目明确要求该技能时仍遵守项目要求，公开版默认不覆盖项目门禁。使用外部技能时记录来源与版本，不把本地自拟说明称为其产物。

沿用用户已选路径和停点，不逐阶段重复询问。目标或授权不明确时，先把固定提交、说明稿和合并预演准备好，再只确认缺失的决定；可选项不授权远端写入，也不绕过项目规则或分支保护。

| 路径 | 使用条件 | 说明与完成条件 |
|---|---|---|
| PR / MR | 用户选择审查请求流程，并授权对应推送、创建、合并阶段 | 说明用于远端正文；按目标读取 [GitHub](github.md) 或 [GitLab](gitlab.md) 的创建/恢复契约。核对分支、SHA、正文及实际状态，合并只在已授权时执行。 |
| 直接进入目标分支 | 用户明确授权本批范围直接推送指定远端分支，且仓库允许 | 同样完成交付说明，保存在项目既有交付位置；各提交保留独立问题说明。成功后记录“已直接推入目标分支”，附远端提交链接。 |

用户可在最终 SHA 产生前授权“本批完成后直接推”。范围、目标和约定条件未变时沿用授权，执行前冻结最终 SHA；用户将授权限定到特定 SHA 时仍按限定执行。

1. 核对当前远端目标 SHA、冻结提交与全部待推送差异，确认审查及回归证据适用，并确认目标是冻结提交的祖先。上游有变化时复核受影响部分；不能快进则停在本地处理。
2. 用普通非强制 push 将完整冻结 SHA 推到精确目标 ref，不以可移动分支名代替受审提交。这条路径直接进入目标分支；分支保护拒绝时报告原错误，保留成果。
3. 写入后重新读取远端目标 SHA，核对目标已包含本批提交；随后有他人提交时核实祖先关系，分别报告本批 SHA 与当前头。结果不明时先回读再决定是否重试。

两条路径的修复、审查和回归要求相同，部署授权单独判断。平台检查、分支保护、合并队列和通知行为按真实远端状态判断；创建 PR/MR、测试通过与合并完成分别记录。续接时先查目标分支是否已包含本批。
