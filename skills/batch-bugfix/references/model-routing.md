# 模型路由

默认沿用当前环境和用户选择的模型。委派只在平台与当前任务规则允许、子任务范围独立、协调者同时有其他有用工作时使用；任务较小时直接在当前对话完成。

项目提供了本工作流的配置时先读取，否则使用环境既有分工。可将 [配置示例](../assets/model-routing.example.json) 复制到目标项目的 `.batch-bugfix/model-routing.json` 并填写实际可用的模型与档位。该 JSON 供 Agent 阅读，不由发布脚本加载，也不改全局设置。

| 角色 | 适合工作 |
|---|---|
| small | 范围清楚的定位、证据整理、明确预期的小改动 |
| standard | 常规复现、修复、回归和独立审查 |
| deep | 根因冲突、跨模块状态、复杂补丁复审 |

配置中的 `model`、`reasoning_effort` 为 null 时继承环境选择。有针对性调查后仍存在具体疑点时才升级角色；凭据、数据或业务决定缺失时处理实际卡点。用户当前指定的配置优先。

委派前核对工具实际支持的模型、档位和参数，按 [分工契约](dispatch.md) 给足基线、原始预期、复现、范围、完成条件与授权。指定组合不可用时说明限制，保留当前对话能完成的工作；不得静默替换明确指定的模型，也不修改全局配置补救。

记录任务 ID、请求配置、选择/升级原因和证据入口。工具没有返回实际模型信息时，只能称为请求配置。审查应由未参与实现的执行者完成；环境不支持独立复核时记录限制，不将自查写成独立审查。
